# Хранение секретов (`deploy/vps/.env`) — кратко для СБ

## Файл на сервере

- Реальный `deploy/vps/.env` **не коммитится**; шаблон — только `deploy/vps/.env.example` (без боевых значений).
- На VPS выставить права **0600** (владелец — пользователь/роль, от имени которого выполняется `docker compose`), группа без лишнего read.

## Ротация

- Пароли и ключи менять по регламенту ИБ; после смены — `docker compose ... up -d` для затронутых сервисов (RabbitMQ, MinIO, Keycloak, Django и т.д. — в зависимости от переменной).
- Старые значения не оставлять в shell history: использовать редактор или `install -m 0600` из временного файла с последующим `shred`/`rm` по политике хоста.

## Направление развития

- Корпоративный **Vault** / Secret Manager / внешний store с inject в runtime — целевой вариант для прод; в репозитории не хранить секреты и не дублировать их в документации.
- CI использует **фиктивные** значения только для `docker compose config` и тестов; не переиспользовать как прод.
