# Организационные меры СБ и границы ответственности (Converter)

Документ связывает типичные **организационные** требования аудита с тем, что делает **команда Converter в репозитории/конфиге**, и с тем, что остаётся на стороне **ИБ / ЦОД / хоста**.

Практические проверки периметра (curl на 443, «закрыты ли белые порты 180xx/256xx/290xx»): см. шпаргалку на рабочем столе рядом с репозиторием — [`converter-perimeter-443-cheatsheet.md`](../converter-perimeter-443-cheatsheet.md) (путь от `converter/docs/`).

| Требование / формулировка | Владелец (типично) | Что делает Converter (артефакты) | Что вне scope кода |
|---------------------------|-------------------|-----------------------------------|---------------------|
| Снаружи только **443** (и при политике — редирект с 80) | ЦОД / сеть + ИБ | `docker-compose.vps.yml`: сервисы на **127.0.0.1**; инструкции в `deploy/vps/README.md`, cheatsheet выше | Firewall/security group на границе, политика «нет публикации лишних портов» |
| **Нет `git pull` с прод/VPS из закрытого ЦОД** к публичному GitHub | Орг. политика / ИБ | Исходники и CI в Git; деплой — `git fetch` с **разрешённого** egress (или зеркало/артефакты) по регламенту | Выделение exit node / зеркала / offline bundle (`Converter-nositel-dlya-SB`) |
| **Администрирование только через терминальный сервер** / bastion | ИБ / ЦОД | SSH-доступ к хосту не настраивается в compose; runbook описывает операции **после** входа на хост | УЗ, MFA на SSH, журналирование сессий, запрет прямого доступа с рабочих станций |
| Разделение ролей **ИБ / разработка** | ИБ + руководство | Документация СБ, чеклисты, approved deploy; без хранения секретов в git | Матрица доступа, утверждение выкатов |
| Аудит образов / SBOM | ИБ + команда | `scripts/security-sbom-scan.sh`, `docs/security-sb-delivery-pack.md`, пины digest в `docker-compose.vps.yml` | Выбор инструмента ИБ, сроки предоставления отчётов |

**Итог:** Converter поставляет **конфигурацию и доказательства** (compose, доки, скрипты проверки); **периметр, bastion, firewall и организационные запреты** закрепляются владельцами инфраструктуры и ИБ.
